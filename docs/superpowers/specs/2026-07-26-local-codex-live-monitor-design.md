# 로컬 Codex 실시간 현황판 설계

## 1. 목적

이 문서는 일반 앱인 `My Codex Agent Monitor`에 실제 로컬 Codex 상태 수집을 추가하는 기능·시스템 스펙이다. [에이전트 세션 목록 정렬 및 상호작용 스펙](./2026-07-25-agent-session-sorting-design.md)의 화면 구조, 정렬, 선택, 접근성 요구사항을 상속하며, 데이터 원천·등록 생명주기·상태 판정·연결 및 복구 동작만 변경한다. 이 문서에서 명시적으로 바꾸지 않은 상위 요구사항은 그대로 유지한다.

`My Codex Agent Monitor`를 Codex가 실행되는 동일 Windows PC에서 사용하는 로컬 현황판으로 만든다.

현황판은 서버 실행 시점에 작업 중인 루트 세션과 하위 에이전트를 찾아 등록하고, 이후 상태 변화를 3초마다 반영한다. 사용자는 현재 어떤 세션이 실행 중인지, 무엇을 하고 있는지, Plan·Goal·토큰·스킬·하위 에이전트 상태가 어떻게 변하는지 기존 `Orbital Dispatch` 화면에서 확인할 수 있어야 한다.

## 2. 성공 기준

- 로컬 모니터 서버 시작 시 현재 활성 상태인 루트 세션만 최초 등록한다.
- 실행 중 새로 시작되거나 재개된 루트 세션을 자동 등록한다.
- 등록된 세션이 `task_complete`가 되면 제거하지 않고 `Complete`로 유지한다.
- 서버 시작 시 `task_complete` 없이 10분 이상 갱신되지 않은 세션은 최초 목록에 등록하지 않는다.
- 한 번 등록된 세션은 시간 경과만으로 제거하지 않으며, 10분 이상 갱신되지 않은 미완료 세션은 `Idle`로 표시한다.
- 하위 에이전트는 상위 목록이 아니라 부모 세션 상세에서만 표시한다.
- 현재 대시보드의 목록·상세 구조, 5행 목록 높이, 정렬, 선택, Live/Paused, 상태 모션을 유지한다.
- 관찰되지 않은 진행률, ETA, 상태, 스킬을 생성하지 않는다.
- `npm run monitor` 한 번으로 빌드, 서버 실행, 브라우저 열기가 완료된다.

## 3. 범위

포함:

- 이 PC의 로컬 Codex 세션
- 모니터 프로세스 실행 중 등록된 루트 세션
- 등록된 루트 세션의 하위 에이전트
- App Server와 로컬 Codex 세션 JSONL을 합친 읽기 전용 수집
- 현재 프로세스 수명 동안의 메모리 기반 세션 목록

제외:

- 원격 접속과 외부 네트워크 공개
- 과거 세션 전체를 보여주는 History
- 모니터 재시작 후 완료 세션 복원
- 별도 영속 저장소
- Codex 작업 시작·중지·승인 같은 쓰기 작업
- Windows 서비스, 트레이 앱, 운영체제 자동 시작
- 작업 진행률 백분율과 완료 예상 시간

## 4. 전체 구조

### 4.1 로컬 실행 서버

Node.js 로컬 서버를 `127.0.0.1:4310`에만 바인딩한다. 이 서버는 다음 책임만 가진다.

- 정적 React 빌드 제공
- Codex App Server 자식 프로세스 관리
- 로컬 Codex 상태 수집
- 정규화된 `/api/snapshot` 제공
- 브라우저 자동 실행과 종료 처리

새 런타임 의존성은 추가하지 않는다. Node.js 표준 모듈과 현재 설치된 패키지만 사용한다.

### 4.2 Codex App Server 클라이언트

로컬 서버는 다음 명령을 자식 프로세스로 실행한다.

```text
codex app-server --listen stdio://
```

JSONL 기반 요청·응답을 사용하며 읽기 메서드만 호출한다.

- `initialize`
- `thread/list`
- `thread/read`
- `thread/goal/get`

App Server는 세션 식별자, 이름, 작업 폴더, 수정 시각, 부모 Thread 관계, Turn 이력, Goal을 제공하는 기본 카탈로그다.

별도 App Server에서 다른 Codex 프로세스의 Thread 상태가 `notLoaded`로 반환될 수 있으므로 이 값만으로 실행 상태를 판정하지 않는다.

### 4.3 로컬 세션 기록 판독

이 문서의 `CODEX_HOME`은 유효 Codex 홈 디렉터리를 뜻한다. `CODEX_HOME` 환경 변수가 설정돼 있으면 그 경로를 사용하고, 설정돼 있지 않으면 현재 Windows 사용자의 기본 Codex 홈인 `%USERPROFILE%\.codex`를 사용한다. 해당 디렉터리의 세션 JSONL을 읽기 전용으로 사용한다.

필요한 사건:

- `task_started`
- `task_complete`
- `user_message`
- `token_count`
- `update_plan` 도구 호출
- 도구 호출과 도구 결과
- `sub_agent_activity`
- `thread_goal_updated`
- 파일 변경과 패치 적용 결과

처음 후보 세션을 등록할 때 현재 상태를 복원하고, 이후에는 파일 크기와 수정 시각을 기준으로 새로 추가된 내용만 읽는다. 마지막 JSONL 줄이 아직 완성되지 않았으면 건너뛰고 다음 수집에서 다시 읽는다.

App Server가 제공하는 부모 관계와 Goal을 우선 사용한다. 동일 정보를 얻기 위해 Codex SQLite 파일을 직접 중복 조회하지 않는다.

### 4.4 스냅샷 조립

App Server Thread와 JSONL 사건을 `threadId`로 결합한다. 서버 응답은 React 컴포넌트나 아이콘을 포함하지 않는 직렬화 가능한 값만 사용한다.

```text
Snapshot
  collectedAt
  connectionStatus
  sessions[]
    identity
    status and activity
    current turn
    token usage
    skills
    plan
    goal
    children[]
    recent activity[]
```

React 아이콘과 색상은 클라이언트가 상태와 역할을 기준으로 선택한다.

## 5. 세션 등록 생명주기

### 5.1 최초 등록

서버 시작 시 App Server의 Thread를 최근 수정 순으로 조회한다. 다음 조건을 모두 만족하는 루트 Thread만 메모리 목록에 등록한다.

- `parentThreadId`가 없다.
- 최신 Turn이 `task_complete`, 구조화된 실패·취소·중단 사건 중 하나로 종료되지 않았다.
- 세션 기록이 최근 10분 내 갱신됐다.

조회 결과는 10분 경계를 지날 때까지 페이지를 순회한다. 고정된 개수만 조회해 활성 세션을 누락하지 않는다.

### 5.2 실행 중 갱신

3초마다 최근 변경 Thread와 이미 등록된 미완료 Thread를 확인한다.

- 모니터 시작 이후 새로 시작되거나 재개된 루트 Thread: 다음 수집 시 이미 종료됐어도 등록하고 확인된 최신 상태를 즉시 적용
- 등록된 Thread의 `task_complete`: `Complete`로 변경하고 유지
- 등록된 미완료 Thread가 10분 이상 갱신 없음: 제거하지 않고 `Idle`로 변경
- 등록된 `Idle` 또는 종료 상태의 Thread가 재개됨: `Running`으로 변경
- 이미 등록된 Thread의 실패·취소·중단이 구조화된 사건으로 확인됨: 해당 종료 상태로 변경하고 유지

한 번 등록된 세션은 모니터 프로세스가 종료될 때까지 목록에 남는다. 모니터를 재시작하면 최초 등록 규칙으로 목록을 새로 만든다.

### 5.3 하위 에이전트

상위 목록에는 루트 Thread만 포함한다. `parentThreadId`와 자손 Thread 조회로 연결된 하위 에이전트는 부모 상세에만 표시한다.

부모가 등록된 동안 발견된 하위 에이전트는 상세 목록에 유지하며 실제 상태를 표시한다. 활성/전체 요약은 현재 상세 목록을 기준으로 계산한다.

하위 에이전트도 같은 생명주기를 사용한다. 시작 시 오래된 미완료 하위 에이전트는 등록하지 않지만, 모니터 시작 이후 새로 시작되거나 재개된 하위 에이전트는 다음 수집 전에 종료됐어도 등록한다. 한 번 등록된 하위 에이전트는 제거하지 않는다. 완료되면 `Complete`, 10분 이상 갱신되지 않은 미완료 상태면 `Idle`, 재개되면 `Running`으로 표시한다.

## 6. 상태 판정

상태는 각 Thread의 가장 최근 Turn에 속한 사건만 사용해 다음 우선순위로 판정한다. 이전 Turn의 승인 요청이나 대기 사건을 새 Turn에 다시 적용하지 않는다.

1. 사용자 입력 또는 승인 요청이 해결되지 않음: `needs_input`
2. 구조화된 실패 사건: `failed`
3. 구조화된 취소 또는 중단 사건: `cancelled` 또는 `stopped`
4. 하위 에이전트 결과를 기다리거나 대기 도구가 활성화됨: `waiting`
5. `update_plan` 처리가 현재 활동임: `planning`
6. `task_complete` 확인: `complete`
7. 미완료 Turn이며 최근 10분 내 갱신됨: `running`
8. 미완료 Turn이며 10분 이상 갱신 없음: `idle`

`task_complete`는 현재 Turn 작업의 정상 종료이지 Thread 삭제가 아니다. 실패·취소·중단도 현재 Turn의 종료로 취급한다. 같은 Thread에 새 `task_started`가 기록되면 다시 `running`으로 전환한다.

현재 단계는 관찰 가능한 도구만 다음 화면 상태로 정규화한다.

- 파일 조회와 검색: `Reading files`
- 일반 도구 호출: `Calling tool`
- 패치와 파일 변경: `Editing`
- 테스트·빌드·검증 명령: `Testing`
- 대기 도구와 하위 에이전트 대기: `Waiting`

내부 추론은 표시하지 않는다.

## 7. 기존 화면 wire

현재 `App.jsx`의 `App`, `SessionRow`, `SessionDetail`, `TaskList`, `ChildAgents`, `LiveStep` 구조를 유지한다. 정적 `sessions`, `simulationEvents`, 데모 타이머를 실제 스냅샷 공급자로 교체한다.

| 화면 항목 | 데이터 원천과 변환 |
|---|---|
| 세션 ID·이름·작업 폴더 | App Server `thread/list`, `thread/read` |
| Agent | 루트는 `Codex / Root agent`, 하위는 `agentNickname`, `agentRole` |
| Session | Thread 이름, 없으면 축약 Thread ID |
| Assigned work | 현재 Turn의 마지막 비구조적 `user_message` |
| 상태 | Turn 생명주기, 승인 요청, 대기 도구, 하위 에이전트 상태 |
| 현재 활동 | 마지막 미완료 도구 또는 마지막 관찰 사건 |
| 세션 시간 | Thread의 모든 Turn에서 루트 에이전트가 실제 작업한 누적 시간. 추론·계획·도구 실행은 포함하고 사용자 입력·승인·하위 에이전트 대기는 제외 |
| Skills | 현재 Turn의 명시적 `$skill` 호출과 확인 가능한 스킬 로드 기록 |
| Tasks | 마지막 `update_plan.arguments.plan` |
| Goal | `thread/goal/get` |
| Tokens | 최신 `token_count.info.total_token_usage`; 전체는 루트와 각 하위 Thread의 최신 합계 |
| 하위 에이전트 | `parentThreadId`, 자손 Thread, `sub_agent_activity` |
| 최근 활동 | 도구·파일·Plan·Goal·하위 에이전트 사건 중 최근 4개 |
| Open in Codex | `codex://threads/{threadId}` |

`<environment_context>`나 `<skill>` 전달 블록처럼 실행 지시가 아닌 구조적 메시지는 Assigned work에서 제외한다. 스킬 사용이 구조화된 기록으로 확인되지 않으면 빈 값으로 둔다. Root agent마다 임의의 개별 별칭이나 역할을 만들지 않는다.

서버는 원시 숫자와 시각을 전달하고 표시 문자열은 기존 모델 계층에서 만든다.

## 8. 클라이언트 상태

React는 다음 상태만 관리한다.

- 최신으로 반영된 스냅샷
- 선택된 루트 세션 ID
- 선택된 하위 에이전트 ID
- 정렬 키와 방향
- Live/Paused
- 연결 상태와 마지막 정상 수집 시각

서버의 `durationSeconds`는 `collectedAt` 시점까지 확정된 세션 누적 작업 시간이다. 현재 루트 에이전트가 작업 중이면 클라이언트는 다음 스냅샷 전까지 로컬 1초 시계로 경과 시간을 더해 표시하고, 새 스냅샷이 오면 확정값으로 보정한다. `Paused`, 연결 오류, 사용자 입력·승인·하위 에이전트 대기, 유휴 및 종료 상태에서는 보간하지 않는다.
- 직전 스냅샷과 비교한 변경 강조 정보

`Live`에서는 3초마다 받은 최신 스냅샷을 반영한다. `Paused`에서는 서버 수집을 중지하지 않고 화면만 고정한다. 다시 `Live`로 전환하면 중간 상태를 재생하지 않고 최신 스냅샷을 바로 적용한다.

선택된 세션은 상태나 정렬 위치가 바뀌어도 그대로 유지한다. 등록된 세션을 시간 경과로 제거하지 않으므로 오래된 기록 때문에 선택이 강제로 변경되지 않는다.

기존 데모 전용 `eventId`, `lastEvent`는 서버 계약에 넣지 않는다. 클라이언트가 이전 스냅샷과 새 스냅샷을 비교해 토큰, Plan, 하위 에이전트, 최근 활동 변경을 강조한다.

## 9. 정렬

기본 운영 순서는 기존 규칙을 유지한다.

1. 사용자 확인 필요, 차단, 실패
2. 실행 중
3. 대기
4. 계획 중
5. 비활성
6. 완료

같은 상태 그룹에서는 최근 활동이 위에 온다. 사용자가 선택한 컬럼 정렬과 5행 내부 스크롤도 유지한다.

## 10. 연결 상태와 오류 처리

화면의 `Demo mode` 표시는 실제 연결 상태로 교체한다.

- `Connected`: 마지막 수집 성공
- `Syncing`: 최초 스냅샷 구성 중
- `Error`: App Server 또는 상태 읽기 실패

오류 처리:

- App Server 종료: 최대 5초의 짧은 재시도 간격으로 재실행
- 일시적 파일 읽기 실패: 마지막 정상 스냅샷 유지
- 불완전한 JSONL 마지막 줄: 다음 수집까지 보류
- 알 수 없는 사건: 무시하되 수집 전체를 실패시키지 않음
- 포트 사용 중: 다른 포트를 임의 선택하지 않고 명확한 오류 후 종료

오류 메시지에는 인증 정보, 전체 사용자 메시지, 로컬 파일 내용이 포함되지 않는다.

## 11. 실행 편의

사용자는 다음 명령 하나만 실행한다.

```text
npm run monitor
```

이 명령은 다음 순서로 동작한다.

1. 기존 애플리케이션 빌드
2. 로컬 수집 서버 실행
3. Codex App Server 자식 프로세스 실행
4. 준비 완료 후 기본 브라우저에서 `http://127.0.0.1:4310` 열기

`Ctrl+C`를 누르면 로컬 서버와 Codex App Server 자식 프로세스를 함께 종료한다.

기존 `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, `tests/sites-worker.test.mjs`는 유지한다. Sites 빌드와 로컬 모니터 실행은 서로 다른 런타임이다.

## 12. 보안과 데이터 경계

- 로컬 서버는 `127.0.0.1`에만 바인딩한다.
- 루프백 바인딩은 외부 네트워크 접근만 차단하며, 같은 PC의 다른 사용자나 로컬 프로세스를 서로 격리한다고 간주하지 않는다.
- App Server는 stdio로만 연결한다.
- App Server에 쓰기 메서드를 호출하지 않는다.
- `CODEX_HOME` 파일과 DB에 쓰지 않는다.
- 별도 로그에 사용자 요청 본문이나 도구 출력을 복제하지 않는다.
- 브라우저에는 대시보드에 필요한 정규화된 정보만 전달한다.

## 13. 검증

### 13.1 수집기

- 시작 시 활성 루트 세션만 등록한다.
- 시작 시 오래된 미완료 루트 세션을 등록하지 않는다.
- 시작 시 최신 Turn이 실패·취소·중단으로 종료된 루트 세션을 등록하지 않는다.
- 최초 목록에서 제외된 세션의 재개를 감지해 등록한다.
- 모니터 시작 이후 한 수집 주기 안에 시작·종료된 루트와 하위 에이전트를 등록하고 해당 종료 상태로 표시한다.
- 등록된 오래된 미완료 세션을 제거하지 않고 `Idle`로 변경한다.
- 등록된 완료 세션을 유지한다.
- 등록된 세션이 실패·취소·중단되면 해당 종료 상태로 유지한다.
- 루트 목록에서 하위 에이전트를 제외한다.
- `CODEX_HOME` 환경 변수 설정 여부에 따라 지정 경로 또는 현재 사용자의 기본 Codex 홈을 읽는다.
- 불완전한 JSONL 줄을 안전하게 재시도한다.
- App Server 재시작 후 수집을 복구한다.

### 13.2 wire 변환

- `update_plan` 상태를 화면의 Done/In progress/Queued로 변환한다.
- Goal 목적·상태·사용량을 실제 값으로 표시한다.
- 루트·하위 에이전트 토큰을 중복 없이 집계한다.
- 확인된 스킬만 표시한다.
- 도구 사건을 Live step으로 정규화한다.
- `complete`·`failed`·`cancelled`·`stopped`의 세션 시간이 각 종료 사건 시각에서 멈춘다.
- 최근 활동에 내부 추론을 포함하지 않는다.

### 13.3 화면

- Live에서 실제 스냅샷이 3초마다 반영된다.
- Paused에서 화면이 고정되고 Live 복귀 시 최신 상태가 적용된다.
- 완료 세션이 기본 정렬에서 아래로 이동한다.
- 등록된 오래된 미완료 세션이 `Idle`로 아래로 이동한다.
- 상태와 정렬 위치가 바뀌어도 선택 세션이 유지된다.
- 하위 에이전트는 선택된 부모 상세에만 표시된다.
- 목록은 헤더를 제외하고 정확히 5행 높이에서 내부 스크롤한다.
- `Open in Codex`가 올바른 Thread 딥 링크를 사용한다.
- `Demo mode`가 실제 연결 상태로 교체된다.

### 13.4 회귀 검증

```text
npm test
npm run build
npm run test:sites
```

마지막으로 `npm run monitor`를 실행해 브라우저에서 실제 로컬 세션 스냅샷, 정렬, 선택, Live/Paused, 하위 에이전트 상세, 콘솔 오류 여부를 확인한다.

## 14. 미결정 항목

- MVP 신뢰 경계: 현재 Windows 사용자만 사용하는 단일 신뢰 사용자 환경으로 한정할지, 같은 PC의 다른 사용자·프로세스에 대한 접근 격리까지 요구할지 결정이 필요하다. 결정 전에는 `127.0.0.1` 바인딩을 사용자·프로세스 단위 접근 통제로 해석하지 않는다.

## 15. 후속 검토 항목과 남은 리스크

- Codex 버전에 따라 App Server 읽기 메서드와 JSONL 사건 형식이 달라질 수 있다. 구현 계획을 시작할 때 지원할 로컬 Codex 버전에서 실제 제공 필드와 누락 시 동작을 확인해야 한다.
- 등록된 세션을 프로세스 수명 동안 제거하지 않으므로 장시간 실행 시 메모리 목록이 계속 커질 수 있다. MVP에서는 별도 보존 정책을 추가하지 않으며, 실제 사용에서 성능이나 탐색 문제가 확인될 때 검토한다.
