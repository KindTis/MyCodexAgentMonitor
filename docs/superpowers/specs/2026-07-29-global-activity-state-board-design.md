# 글로벌 활동 상태 보드 설계

## 1. 목적

이 문서는 `My Codex Agent Monitor`의 선택되지 않은 세션 영역에 글로벌 활동 화면을 추가하는 기능·화면 delta 스펙이다. 기존 `Orbital Dispatch`의 루트 세션 목록과 선택 세션 상세 구조는 유지한다.

사용자가 아무 세션도 선택하지 않았을 때 여러 루트 에이전트가 각자의 작업을 수행하고 있다는 인상을 즉시 받을 수 있어야 한다. 이를 위해 루트 세션을 실제 상태별 레인에 배치하고, 상태 변화에 따라 카드가 레인 사이를 이동하는 실시간 상태 보드를 제공한다.

이 보드는 일반 칸반처럼 순차적인 진행 단계를 뜻하지 않는다. 상태는 진행률이 아니며 세션은 어떤 레인으로든 이동하거나 이전 레인으로 돌아갈 수 있다.

## 2. 성공 기준

- 최초 진입 시 루트 세션을 자동 선택하지 않고 글로벌 상태 보드를 표시한다.
- 글로벌 상태 보드는 모든 루트 세션을 6개 상태 레인에 정확히 배치한다.
- 같은 레인 안에서는 최근 활동 세션이 먼저 보인다.
- 상태 변경 시 세션 카드가 중복 없이 새 레인으로 이동한다.
- 카드의 최신 이벤트 변화가 짧은 강조로 드러난다.
- 루트 세션 목록 또는 글로벌 카드에서 세션을 선택하면 기존 상세 화면을 표시한다.
- 선택을 해제하거나 상세 화면을 닫으면 글로벌 상태 보드로 돌아간다.
- `Live / Paused`, 연결 오류, 모션 감소 설정과 기존 시간 표시 규칙을 유지한다.
- 관찰되지 않은 진행률·이벤트·상태·ETA를 만들지 않는다.

## 3. 범위

포함:

- 선택되지 않은 상태의 글로벌 루트 세션 보드
- 6개 상태 레인과 카드 배치
- 글로벌 카드의 최신 활동 표시
- 선택·재선택·닫기에 따른 글로벌 보드와 기존 상세 화면 전환
- 실제 스냅샷 변화에 연결된 카드 이동·재정렬·이벤트 강조
- 데스크톱과 작은 화면의 반응형 레인 배치

제외:

- 서버 API와 스냅샷 데이터 구조 변경
- Child Agent를 글로벌 보드에 표시하는 기능
- 루트 세션 작업을 시작·중지·승인하는 제어 기능
- 진행률 백분율, 처리량 KPI, ETA
- 별도 이벤트 저장소와 과거 활동 History
- 새 런타임 의존성

## 4. 화면 구조

데스크톱의 기존 master-detail 구조를 유지한다.

- 왼쪽: 기존 루트 세션 목록
- 오른쪽, 선택 없음: 글로벌 활동 상태 보드
- 오른쪽, 선택 있음: 기존 선택 세션 상세 화면

글로벌 보드 헤더에는 화면 이름, Live 또는 Paused 상태, 마지막 적용 스냅샷 상대 시각만 표시한다. 별도의 KPI 카드나 임의 활동률은 추가하지 않는다.

레인 순서는 기존 운영 기본 정렬과 같다.

1. Attention
2. Working
3. Waiting
4. Planning
5. Inactive
6. Complete

모든 레인은 비어 있어도 유지하고 `No sessions`를 표시한다. 루트 세션이 하나도 없으면 레인 대신 보드 전체 빈 상태를 표시한다.

## 5. 상태 레인 매핑

기존 `normalizeStatus` 결과를 다음과 같이 배치한다.

| 레인 | 상태 |
| --- | --- |
| Attention | `needs_input`, `blocked`, `failed` |
| Working | `running` |
| Waiting | `waiting` |
| Planning | `planning`, `queued` |
| Inactive | `idle`, `paused` |
| Complete | `complete`, `cancelled`, `stopped` |

Attention과 Complete처럼 여러 상태를 묶는 레인에서도 카드에는 정확한 상태 배지를 표시한다. `Failed`, `Cancelled`, `Stopped`를 일반 완료처럼 보이게 만들지 않는다.

같은 레인에서는 `lastActivityAt`이 최근인 세션을 먼저 배치한다. 시각이 같거나 없으면 기존 `sortSessions`의 안정적인 보조 정렬 규칙을 재사용한다.

## 6. 글로벌 세션 카드

카드는 좁은 레인에서도 현재 작업과 최신 활동을 읽을 수 있는 최소 정보만 표시한다.

- 프로젝트명
- Git 브랜치
- 현재 작업 제목
- 정확한 상태 배지
- 최신 활동 이벤트와 상대 시각
- 세션 작업 시간

현재 작업 제목은 `currentWork.title`, 할당 작업, 세션명 순으로 폴백한다. 최신 활동은 관찰된 `currentActivity` 또는 가장 최근 활동 항목만 사용한다. 브랜치·작업·이벤트가 없으면 기존 화면의 폴백 문구를 재사용한다.

Skills, Plan Tasks, Goal, Token, Child Agent 수와 긴 활동 이력은 기존 루트 세션 목록과 상세 화면에 맡긴다. 카드 텍스트는 레인 폭 안에서 최대 두 줄로 제한하고 가로 스크롤을 만들지 않는다.

글로벌 카드는 버튼으로 제공한다. 카드를 선택하면 왼쪽 목록에서 같은 루트 세션을 선택한 것과 동일하게 기존 상세 화면을 연다.

## 7. 선택과 화면 전환

애플리케이션은 다음 규칙을 사용한다.

1. 최초 진입: `selectedSessionId`가 `null`이며 글로벌 상태 보드를 표시한다.
2. 루트 목록 또는 글로벌 카드 선택: 해당 세션 상세 화면을 표시한다.
3. 선택된 루트 목록 행을 다시 선택: 선택을 해제하고 글로벌 상태 보드로 돌아간다.
4. 상세 헤더의 닫기 버튼 선택: 선택을 해제하고 글로벌 상태 보드로 돌아간다.
5. 다른 루트 세션 선택: 해당 상세 화면으로 즉시 전환한다.
6. 선택 세션이 적용된 스냅샷에서 사라짐: 기존 안내를 표시하고 선택을 해제한다.
7. 루트 선택을 바꾸거나 해제함: 열려 있던 Child Agent dialog도 닫는다.

현재 첫 번째 가시 세션을 자동 선택하는 동작은 제거한다. `Live / Paused`는 스냅샷 적용만 제어하며 선택을 임의로 변경하지 않는다.

목록 행과 글로벌 카드는 `aria-pressed`로 선택 상태를 전달하고 같은 상세 영역을 `aria-controls`로 연결한다. 상세 닫기 버튼에는 명확한 접근성 이름을 제공한다.

## 8. 활동 피드백과 모션

모션은 실제 적용된 스냅샷 변화에만 반응한다.

- 상태 변경: 기존 카드 위치에서 새 레인 위치로 이동
- 같은 레인의 최신 활동 갱신: 최근 활동 순으로 재정렬
- 새 이벤트: 해당 카드의 최신 이벤트 줄만 짧게 강조
- 실제 작업 중: 상태 점에 절제된 맥동 표시

중간 상태를 재생하거나 장식용 이벤트를 만들지 않는다. `Paused`에서는 새 스냅샷을 적용하지 않으므로 카드 배치·이벤트·재정렬도 멈춘다. Live 복귀 시 중간 변화를 순서대로 재생하지 않고 마지막 적용 상태에서 최신 스냅샷 위치로 한 번만 갱신한다.

카드 이동은 현재 세션 목록 재정렬에 사용하는 GSAP 위치 전환 패턴을 재사용한다. 새 모션 의존성이나 전역 애니메이션 계층은 추가하지 않는다. `prefers-reduced-motion: reduce`에서는 위치 애니메이션 없이 즉시 재배치하고 정보 변화 자체는 유지한다.

## 9. 반응형 배치와 스크롤

- 넓은 데스크톱: 6개 레인을 한 줄로 배치한다.
- 기존 master-detail이 세로로 쌓이는 폭: 3열 × 2행으로 배치한다.
- 작은 화면: 2열로 배치한다.
- 모바일: 1열로 배치한다.

데스크톱에서 카드가 레인 높이를 넘으면 각 레인의 카드 영역만 세로로 스크롤하고 레인 헤더는 유지한다. 작은 화면에서는 레인 내부의 고정 높이와 내부 스크롤을 제거해 페이지가 자연스럽게 늘어나게 한다.

## 10. 구성 요소와 데이터 흐름

새 서버 계층이나 데이터 모델은 만들지 않는다.

```text
snapshot.sessions
  → getVisibleSessions
  → normalizeStatus
  → 상태 레인 매핑
  → 레인별 최근 활동 정렬
  → GlobalActivityBoard
```

변경 책임:

- `src/agent-model.js`: 정규화된 상태를 레인 ID로 매핑하는 작은 순수 함수
- `src/App.jsx`: 글로벌 보드와 글로벌 세션 카드, 선택 해제와 닫기 동작
- `src/styles.css`: 보드·레인·카드·모션 감소·반응형 스타일
- 기존 테스트: 상태 매핑, UI 출력, 레이아웃 계약과 회귀 검증

`App`은 `selectedSession`이 있으면 기존 `SessionDetail`, 없으면 `GlobalActivityBoard`를 렌더링한다. 현재 `changes` 결과를 카드 이벤트 강조에 재사용한다. 카드 위치 전환은 보드 전용 요소 참조와 이전 위치만 추가로 추적하며 기존 목록 정렬 동작을 변경하지 않는다.

## 11. 오류와 경계 동작

- 연결 오류: 기존처럼 마지막 정상 스냅샷을 유지하므로 보드도 마지막 정상 상태를 유지한다.
- 연결 복구: 최신 정상 스냅샷을 한 번 적용하고 중간 이동을 재생하지 않는다.
- 알 수 없는 상태: 기존 `normalizeStatus` 폴백을 거친 뒤 Inactive에 배치한다.
- 누락된 표시 값: 기존 폴백 문구를 사용하고 임의 값을 만들지 않는다.
- 빈 레인: 레인을 제거하지 않고 빈 상태를 표시한다.
- 세션 없음: 보드 전체 빈 상태를 표시한다.
- 긴 텍스트: 최대 두 줄로 제한하고 레이아웃을 넓히지 않는다.

## 12. 검증

### 12.1 모델

- 모든 알려진 상태가 합의한 6개 레인에 매핑된다.
- 알 수 없는 상태가 기존 정규화 규칙을 거쳐 Inactive에 배치된다.
- 같은 레인에서 최근 활동 세션이 먼저 정렬된다.

### 12.2 UI와 상호작용

- 최초 화면에 6개 레인과 글로벌 상태 보드가 나타난다.
- 첫 번째 루트 세션을 자동 선택하지 않는다.
- 글로벌 카드가 프로젝트, 브랜치, 현재 작업, 정확한 상태, 최신 이벤트, 세션 시간을 표시한다.
- 루트 목록과 글로벌 카드 선택이 기존 상세 화면을 연다.
- 같은 목록 행 재선택과 상세 닫기가 글로벌 보드로 돌아간다.
- 선택 세션이 사라지면 선택을 해제하고 기존 안내를 표시한다.
- 루트 선택 전환과 해제가 Child Agent dialog를 닫는다.
- `Paused`에서는 배치와 이벤트가 갱신되지 않는다.

### 12.3 레이아웃과 모션

- 데스크톱 6열, 중간 폭 3열, 작은 화면 2열, 모바일 1열 계약을 확인한다.
- 데스크톱에서는 넘치는 카드 영역만 스크롤한다.
- 카드 이동 후 같은 세션이 두 레인에 중복되지 않는다.
- 새 이벤트만 짧게 강조한다.
- 모션 감소 설정에서는 즉시 재배치한다.

### 12.4 회귀 검증

```text
npm test
npm run build
npm run test:sites
```

마지막으로 로컬 모니터 서버를 직접 실행해 브라우저에서 다음을 확인한다.

- 초기 글로벌 보드
- 목록·글로벌 카드 선택과 상세 닫기
- 실제 상태 변경에 따른 레인 이동
- 같은 레인 내 최근 활동 재정렬
- Live/Paused 전환
- 반응형 레인 배치
- 브라우저 콘솔 오류 없음

## 13. 결정 사항

- K2 전체 상태 보드를 사용한다.
- 상태 보드는 진행 단계가 아니라 실제 상태 분류다.
- 모든 루트 세션을 6개 레인에 표시한다.
- 글로벌 카드는 활동 맥락에 필요한 최소 정보만 표시한다.
- 글로벌 카드와 기존 목록 모두 상세 화면 진입점이다.
- 모션은 실제 상태·이벤트 변화에만 연결한다.
- 백엔드, 스냅샷 계약, 의존성은 변경하지 않는다.
