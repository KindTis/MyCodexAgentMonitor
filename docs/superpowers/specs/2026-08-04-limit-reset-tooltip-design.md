# 상단 Limit 리셋 툴팁 설계

## 목표

상단의 `5H`·`1W` Limit 사용량 영역에 마우스를 올리거나 키보드로 포커스하면 각 제한 창의 다음 리셋까지 남은 시간을 표시한다.

## 데이터 흐름

기존 `account/rateLimits/read` 응답의 300분·10,080분 창에서 `usedPercent`와 함께 `resetsAt`을 읽는다. `resetsAt`은 Unix 초 단위이며, 기존 최상위 `usage` 스냅샷에 다음 필드로 전달한다.

```js
usage: {
  fiveHourUsedPercent: 21,
  fiveHourResetsAt: 1785771600,
  oneWeekUsedPercent: 6,
  oneWeekResetsAt: 1786203600
}
```

필드가 없거나 유효한 비음수 숫자가 아니면 해당 값만 `null`로 처리한다. 다른 사용량 값과 수집 주기는 변경하지 않는다.

## 표시와 상호작용

- Limit 그룹 전체를 툴팁 트리거로 사용한다.
- 툴팁은 CSS의 hover와 focus 상태로만 열며 별도 React 상태나 이벤트 핸들러를 만들지 않는다.
- 툴팁에는 `5H reset`과 `1W reset` 두 행을 표시한다.
- 남은 시간은 `DD:HH:MM` 형식으로 표시한다. 일·시·분은 각각 최소 두 자리이며, 초는 버린다.
- 기존 `wallClock`과 `resetsAt`의 차이를 사용한다. 이미 지난 리셋 시각은 `00:00:00`으로 표시한다.
- 리셋 정보가 없으면 해당 행의 값은 `-`로 표시한다.
- 툴팁은 기존 네이비 배경, 구분선, Geist Sans/Mono를 재사용하고 장식 효과나 애니메이션을 추가하지 않는다.
- 키보드 사용자도 확인할 수 있도록 트리거에 포커스를 허용하고 툴팁을 `aria-describedby`로 연결한다.

## 검증

- 300분·10,080분 창의 `resetsAt` 매핑과 누락·오류 시 `null` 처리를 검증한다.
- 고정된 현재 시각을 기준으로 남은 시간이 `DD:HH:MM`으로 렌더링되는지 검증한다.
- 지난 시각은 `00:00:00`, 없는 값은 `-`인지 검증한다.
- 툴팁의 접근성 연결과 두 행의 레이블을 정적 마크업에서 확인한다.
- `npm test`, `npm run build`, `npm run test:sites`를 실행한다.

## 범위 제외

- 마우스 위치를 따라가는 툴팁
- 별도 카운트다운 타이머
- 리셋 알림 또는 기록
- Limit 수집 주기 변경
