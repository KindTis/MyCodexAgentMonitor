# 에이전트 세션 목록 정렬 및 상호작용 스펙

## 1. 목적

Codex App Server가 현재 반환하는 세션 스냅샷을 운영 중요도에 따라 정렬한다. 사용자는 기본 운영 순서를 유지하면서 필요할 때 각 컬럼을 기준으로 목록을 다시 정렬할 수 있어야 한다.

이 기능은 다음 질문에 빠르게 답하는 것을 목표로 한다.

- 지금 사용자 확인이나 조치가 필요한 세션은 무엇인가?
- 현재 실행 중인 세션은 무엇인가?
- 어떤 세션이 오래 대기하거나 멈춰 있는가?
- 어느 세션이 많은 태스크나 하위 에이전트를 가지고 있는가?

## 2. 데이터 범위

대시보드는 영속 저장소가 아니라 현재 Codex App Server 상태의 스냅샷이다.

- 현재 서버 응답에 존재하는 세션만 사용한다.
- 서버 재시작 전의 세션 정보는 유지하지 않는다.
- 완료·중단 세션도 현재 서버 응답에 포함된 동안은 표시한다.
- History, 보관 기간, TTL, 페이지네이션은 제공하지 않는다.
- 정렬 선택도 로컬 저장하지 않는다. 화면을 새로고침하면 기본 운영 순서로 돌아간다.

## 3. 상위 목록 포함 기준

상위 목록의 한 행은 에이전트가 아니라 하나의 독립 루트 세션을 나타낸다.

포함 조건:

- 유효한 `sessionId`를 가진 현재 서버 세션
- `parentSessionId`가 없거나 루트로 명시된 세션

제외 조건:

- 다른 세션에 소속된 하위 에이전트 세션
- 세션 식별자가 없어서 상세 화면과 연결할 수 없는 레코드
- 현재 서버 응답에서 이미 사라진 세션

하위 에이전트는 부모 세션의 상세 화면에서만 표시한다. 상위 목록에는 다음 요약만 표시한다.

```text
활성 하위 에이전트 수 / 전체 하위 에이전트 수
```

활성 수에 포함하는 상태:

- `running`
- `waiting`
- `planning`
- `needs_input`
- `blocked`

활성 수에서 제외하는 상태:

- `queued`
- `idle`
- `paused`
- `complete`
- `cancelled`
- `stopped`
- `failed`

전체 수에는 현재 스냅샷에 존재하는 모든 하위 에이전트를 포함한다.

## 4. 기본 운영 정렬

기본 정렬 모드의 이름은 `Operational order`이다.

### 4.1 상태 우선순위

| 순위 | 그룹 | 상태 |
|---:|---|---|
| 1 | 관심 필요 | `needs_input`, `blocked`, `failed` |
| 2 | 실행 중 | `running` |
| 3 | 실행 대기 | `waiting` |
| 4 | 준비 중 | `planning`, `queued` |
| 5 | 비활성 | `idle`, `paused` |
| 6 | 종료 | `complete`, `cancelled`, `stopped` |

같은 그룹 안에서는 다음 순서를 사용한다.

1. `lastActivityAt` 내림차순
2. `startedAt` 내림차순
3. `sessionId` 오름차순

따라서 같은 상태라면 최근에 활동한 세션이 위에 있고 오래된 세션이 아래에 놓인다. 누락된 시각은 해당 그룹의 마지막으로 처리한다.

### 4.2 갱신 시 동작

- 새 서버 스냅샷이 도착할 때마다 현재 정렬 기준으로 목록을 다시 계산한다.
- 선택한 세션이 계속 존재하면 정렬 위치가 바뀌어도 선택과 상세 화면을 유지한다.
- 선택한 세션이 서버 응답에서 사라지면 새 목록의 첫 번째 세션을 선택한다.
- 이때 `선택한 세션이 현재 서버 상태에서 사라졌습니다`라는 일회성 안내를 표시한다.
- 표시할 세션이 없으면 상세 화면 대신 `현재 서버에 표시할 세션이 없습니다`라는 빈 상태를 보여준다.

### 4.3 Live / Paused

상단의 `Live / Paused` 제어는 현재 들어오는 스냅샷을 화면에 반영할지 결정한다.

- `Live`: 새 스냅샷을 즉시 반영하고 정렬·상세·최근 활동을 함께 갱신한다.
- `Paused`: 마지막으로 반영한 스냅샷을 고정한다. 서버 연결을 끊거나 작업을 중지하지 않는다.
- `Paused` 상태에서 들어온 중간 스냅샷을 재생하거나 누적하지 않는다.
- 다시 `Live`로 전환하면 그 시점의 최신 스냅샷부터 반영한다.
- 현재 모드와 샘플 데이터 여부를 텍스트로 함께 표시한다.

실제 Codex App Server가 연결되지 않은 정식 애플리케이션의 `Demo mode`에서는 동일한 서버 형태의 결정적 샘플 이벤트 순서를 사용한다. 무작위 진행률이나 임의 ETA는 생성하지 않는다.

### 4.4 목록의 활동 표현

목록은 상태 변화가 실제로 일어났을 때만 짧게 반응한다.

- `running`: 상태 아이콘이 천천히 회전하고 행 왼쪽에 약한 실행 펄스를 표시한다.
- `waiting`: 상태 배지가 느리게 호흡한다.
- `needs_input`, `blocked`, `failed`: 해당 상태로 전환될 때만 호박색 또는 적색으로 한 번 강조한다. 지속 점멸하지 않는다.
- 새 이벤트가 반영된 행: 한 번 강조한 뒤 원래 표면으로 돌아간다.
- 운영 우선순위가 바뀐 행: 새 위치로 부드럽게 이동한다.
- `prefers-reduced-motion`에서는 위 애니메이션을 제거하고 정적 상태 차이만 유지한다.

## 5. 사용자 정렬

컬럼 헤더는 키보드와 포인터로 조작할 수 있는 정렬 버튼이다.

지원하는 컬럼:

- Agent
- Session & assigned work
- Status & current activity
- Session time
- Skills
- Tasks
- Goal
- Subagents

헤더를 처음 선택하면 해당 컬럼의 기본 방향으로 정렬하고, 다시 선택하면 방향을 반대로 바꾼다.

| 컬럼 | 첫 정렬 | 비교 값 |
|---|---|---|
| Agent | 오름차순 | 에이전트 이름 |
| Session & assigned work | 오름차순 | 세션 이름, 할당 작업 |
| Status & current activity | 운영 우선순위 | 상태 그룹, 최근 활동 시각 |
| Session time | 내림차순 | 세션 실행 시간 |
| Skills | 내림차순 | 사용 스킬 수 |
| Tasks | 내림차순 | 남은 태스크 수 |
| Goal | 운영 우선순위 | `active`, `paused`, `complete`, 미사용 |
| Subagents | 내림차순 | 활성 수, 전체 수 |

추가 규칙:

- 값이 없는 세션은 정렬 방향과 관계없이 항상 마지막에 둔다.
- 값이 같으면 `lastActivityAt` 내림차순과 `sessionId` 오름차순을 안정적인 보조 기준으로 사용한다.
- 사용자 정렬이 활성화되면 해당 헤더에 방향 아이콘과 `aria-sort`를 표시한다.
- 목록 상단에 현재 정렬 기준을 표시한다.
- `Operational order` 버튼을 선택하면 기본 운영 정렬로 즉시 복귀한다.
- 정렬 변경은 선택된 세션을 바꾸지 않는다.

## 6. 목록 표시 보완

상위 목록의 데이터 영역은 정확히 5행 높이로 고정한다.

- 컬럼 헤더는 5행 높이에 포함하지 않고 항상 노출한다.
- 세션이 5개를 초과하면 데이터 영역 안에서만 세로 스크롤한다.
- 세션이 5개보다 적어도 영역 높이를 유지해 상세 화면의 시작 위치가 바뀌지 않게 한다.
- 선택된 세션이 정렬이나 스냅샷 갱신으로 보이는 범위를 벗어나면 목록 내부에서 해당 행을 노출한다.

기본 순서가 사용자에게 설명 가능하도록 현재 활동 문구에 최근 활동 시각을 함께 표시한다.

```text
Waiting for 2 child agents · 12s ago
```

시각 정보가 없으면 상대 시각을 표시하지 않는다. 임의의 가짜 진행률이나 추정 시간은 만들지 않는다.

상대 시각은 화면이 열려 있는 동안 갱신한다. 초 단위 활동은 `12s ago`, 분 단위 활동은 `4m ago`, 시간 단위 활동은 `2h ago`처럼 표시한다.

## 7. 선택 세션의 라이브 상세

선택 세션 상세는 기존 작업·토큰·스킬·Plan Task·Goal·하위 에이전트·최근 활동을 유지하면서 현재 실행 단계를 추가한다.

### 7.1 Live step

현재 단계는 관찰 가능한 실행 사건으로만 표시한다.

```text
Reading files → Calling tool → Editing → Testing → Waiting
```

- 현재 단계 하나만 활성 상태로 표시한다.
- 도구 호출 단계에서는 도구 이름과 경과 시간을 함께 표시한다.
- 관찰할 수 없는 내부 추론 단계나 임의의 진행률은 표시하지 않는다.
- 세션이 `complete`, `cancelled`, `stopped` 상태이면 단계 표현을 정적으로 종료한다.

### 7.2 갱신 피드백

- 토큰 값이 달라지면 변경된 숫자만 짧게 강조한다.
- Plan Task가 완료되면 체크 전환을 한 번 보여주고 다음 태스크를 활성 상태로 바꾼다.
- 새 최근 활동은 목록의 맨 위에 삽입하고 한 번 강조한다.
- 세션 상태나 현재 단계가 바뀌어도 상세 패널의 선택과 스크롤 맥락은 유지한다.

### 7.3 하위 에이전트

하위 에이전트가 있는 선택 세션에서만 다음 활동 표현을 사용한다.

- 각 행에 현재 단계와 마지막 활동 상대 시각을 표시한다.
- 실행 중인 하위 에이전트는 약한 활동 링을 표시한다.
- 결과를 부모에게 반환하면 짧은 handoff 펄스를 한 번 표시한다.
- 완료된 하위 에이전트는 애니메이션을 멈추고 정적 상태로 둔다.
- 상위 목록의 `활성/전체` 값이 바뀌면 해당 숫자만 한 번 강조한다.

## 8. 상태 정규화

서버 상태와 화면 상태의 차이는 정렬 함수 진입 전에 한 번만 정규화한다.

예시:

- `input`, `approval_required` → `needs_input`
- `working`, `executing` → `running`
- `done`, `completed` → `complete`
- 알 수 없는 상태 → `idle`

알 수 없는 상태는 오류를 발생시키거나 목록에서 제거하지 않는다. `idle`로 표시하고 운영 순서의 아래쪽에 둔다.

## 9. 구현 경계

정렬과 포함 판단은 UI 컴포넌트에서 직접 수행하지 않고 순수한 세션 모델 함수가 담당한다.

필요한 책임:

- 서버 레코드를 화면 상태로 정규화
- 루트 세션만 선택
- 하위 에이전트의 활성/전체 수 계산
- 운영 우선순위 계산
- 선택한 컬럼과 방향에 따른 안정 정렬

React 화면은 다음 상태만 관리한다.

- 선택된 세션 ID
- 현재 정렬 키와 방향
- 현재 반영된 스냅샷
- `Live / Paused` 모드
- 선택 세션 소멸 안내

정렬 함수는 원본 스냅샷 배열을 변경하지 않는다.

## 10. 접근성

- 각 정렬 헤더는 실제 `button`으로 제공한다.
- 활성 컬럼은 `aria-sort="ascending"` 또는 `aria-sort="descending"`을 가진다.
- 기본 운영 정렬 상태는 별도 텍스트로 안내한다.
- 방향 아이콘만으로 상태를 전달하지 않고 텍스트 레이블을 함께 사용한다.
- 키보드 포커스 스타일을 유지한다.
- `Live / Paused`는 실제 버튼이며 현재 상태를 `aria-pressed`와 텍스트로 전달한다.
- 상대 시각의 잦은 갱신은 스크린 리더의 라이브 영역으로 읽지 않는다.
- 행 재정렬과 상태 애니메이션은 `prefers-reduced-motion`에서 비활성화한다.

## 11. 검증 기준

모델 테스트:

- 루트 세션만 상위 목록에 포함된다.
- 하위 에이전트의 활성/전체 수가 상태 기준에 맞게 계산된다.
- 관심 필요 세션이 실행 중 세션보다 위에 배치된다.
- 같은 그룹에서는 최근 활동 세션이 위에 배치된다.
- 완료·중단·오래된 세션은 아래에 배치된다.
- 컬럼별 오름차순과 내림차순이 정확하다.
- 누락된 값은 항상 마지막에 배치된다.
- 정렬 함수가 입력 배열을 변경하지 않는다.

상호작용 검증:

- 헤더를 선택하면 정렬 방향이 전환된다.
- `Operational order`로 기본 정렬이 복원된다.
- 정렬해도 선택된 세션이 유지된다.
- 선택된 세션이 스냅샷에서 사라지면 새 첫 행으로 이동하고 안내가 표시된다.
- 빈 스냅샷에서 빈 상태가 표시된다.
- `Paused`에서는 샘플 스냅샷이 바뀌지 않고 `Live` 복귀 후 다시 갱신된다.
- 선택 세션의 단계·토큰·태스크·최근 활동이 같은 스냅샷 사건으로 함께 바뀐다.
- 하위 에이전트가 없는 세션에는 하위 에이전트 활동 표현이 나타나지 않는다.
- 키보드만으로 정렬, Live/Paused, 세션 선택, 하위 에이전트 상세 열기가 가능하다.
- reduced motion 환경에서 반복·재정렬 애니메이션이 실행되지 않는다.
- 데스크톱과 모바일에서 정렬 컨트롤이 잘리거나 겹치지 않는다.

## 12. 제외 범위

- 서버 측 영속 저장
- 이전 App Server 실행 기록
- History 화면
- 사용자 고정 및 수동 드래그 정렬
- 복합 다중 컬럼 정렬
- 필터 검색
- 페이지네이션
- 실제 Codex App Server 연결
