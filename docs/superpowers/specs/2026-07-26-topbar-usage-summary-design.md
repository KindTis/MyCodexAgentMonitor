# 상단 Codex 사용량 요약 설계

## 목표

기존 상단의 세션 상태 수치를 유지하면서 로컬 Codex의 오늘 토큰·비용과 5시간·1주 사용 한도를 추가한다.

표시 순서는 다음과 같다.

`2 running 0 waiting 2 sessions | Tokens 522,555,501 · Cost $369.2616 | 5H 21% · 1W 6% | 21:19:44 KST`

각 값은 실제 데이터로 표시하며 예시 숫자를 고정하지 않는다.

## 데이터 원천과 독립성

- 오늘 토큰·비용은 이 프로젝트에 설치한 `ccusage`를 로컬에서 실행해 `codex daily --json` 결과의 한국시간 기준 오늘 행을 사용한다.
- 5시간·1주 Limit은 현재 프로젝트가 이미 관리하는 Codex App Server 연결에 `account/rateLimits/read` 요청을 추가해 가져온다.
- `C:\Users\tatis\Repos\MyCodex`의 서버, API, 빌드 결과 또는 소스 파일을 실행 중에 호출하거나 import하지 않는다. 해당 프로젝트는 데이터 형식과 파싱 동작의 참고 자료로만 사용한다.

## 수집과 스냅샷

세션 스냅샷의 3초 수집 주기는 유지한다. 별도의 사용량 수집 상태를 두고 다음 두 작업을 함께 10초마다 실행한다.

1. `ccusage`에서 오늘 토큰·비용 조회
2. 기존 Codex App Server 연결에서 Limit 조회

두 작업은 독립적으로 처리한다. 한쪽 실패가 세션 모니터나 다른 사용량 값의 성공 결과를 실패로 바꾸지 않는다. 사용량 수집 결과는 기존 `/api/snapshot` 응답의 최상위 `usage` 필드에 포함한다.

```js
usage: {
  collectedAt: "2026-07-26T12:19:44.000Z",
  todayTokens: 522555501,
  todayCostUsd: 369.2616,
  fiveHourUsedPercent: 21,
  oneWeekUsedPercent: 6
}
```

조회 전이거나 실패한 값은 `null`이다. 이전 성공 값을 유지하지 않는다.

## 파싱과 표시

- `ccusage` 오늘 행은 한국시간 날짜를 기준으로 선택한다.
- 토큰은 정수로 반올림한 뒤 영어권 천 단위 구분자를 적용한다.
- 비용은 미국 달러 기호와 소수점 네 자리로 표시한다.
- Limit은 `codex` 버킷에서 300분 창을 `5H`, 10,080분 창을 `1W`로 선택하고 정수 백분율로 표시한다.
- 현재 시각은 `Asia/Seoul` 시간대의 `HH:mm:ss KST` 형식으로 표시한다.
- 조회 전 또는 실패한 값은 해당 위치에 `—`로 표시한다.
- 기존 `running`, `waiting`, `sessions` 계산은 변경하지 않는다.
- 작은 화면에서도 사용량 그룹을 숨기지 않고 상단 바가 줄바꿈되도록 한다.

## 오류 처리

- `ccusage` 실행 실패, 시간 초과, JSON 오류, 오늘 행 오류 시 토큰과 비용만 `null`로 만든다.
- App Server 요청 실패, `codex` 버킷 누락, 지원하지 않는 창 또는 잘못된 백분율은 해당 Limit만 `null`로 만든다.
- 사용량 오류 때문에 세션 스냅샷의 연결 상태를 `error`로 변경하지 않는다.
- 다음 10초 수집에서 자동으로 다시 시도한다.

## 검증

- `ccusage` 오늘 행과 비용 필드 파싱을 검증한다.
- 300분·10,080분 창 매핑과 잘못된 응답의 `null` 처리를 검증한다.
- 한 데이터 원천만 실패했을 때 다른 값이 유지되는지 검증한다.
- `/api/snapshot`에 `usage`가 포함되는지 검증한다.
- 상단 표시 형식, 한국시간 및 실패 시 `—` 표시를 확인한다.
- `npm test`, `npm run build`, `npm run test:sites`를 통과시킨다.
