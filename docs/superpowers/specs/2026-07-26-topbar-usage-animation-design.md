# 상단 사용량 숫자 전환 설계

## 목표

상단 `Tokens`와 `Cost`가 새 스냅샷 값으로 즉시 바뀌지 않고, 현재 표시값에서 새 값까지 1,500ms 동안 빠르게 전환되도록 한다. 값이 변하는 순간에는 기존 공통 하이라이트 효과를 함께 적용한다.

## 동작

- 증가와 감소 모두 같은 1,500ms 전환을 적용한다.
- 값 차이와 관계없이 전환 시간은 고정한다. 큰 차이는 중간 숫자를 건너뛰어 제한 시간 안에 목표값에 정확히 도달한다.
- 전환 중 새 값이 들어오면 현재 화면에 표시된 값에서 새 목표값으로 전환을 다시 시작한다.
- 이전 값과 새 값이 같으면 전환과 하이라이트를 시작하지 않는다.
- 숫자와 결측 표시 `—` 사이의 전환은 보간하지 않는다. 값을 즉시 바꾸고 하이라이트만 적용한다.
- 최초 `—`에서 숫자로 바뀔 때도 숫자는 즉시 표시하고 하이라이트만 적용한다.
- Token은 기존 정수·천 단위 구분자 형식을, Cost는 기존 달러·소수점 네 자리 형식을 전환 중에도 유지한다.
- `Live / Paused`의 기존 의미는 바꾸지 않는다. Paused 중에는 새 스냅샷을 적용하지 않으며, Live로 돌아와 값이 달라질 때 전환을 시작한다.

## 구현 구조

`src/App.jsx`의 `SystemSummary` 안에서 Token과 Cost의 표시만 담당하는 작은 숫자 표시 컴포넌트를 사용한다. 기존에 설치되어 있고 같은 파일에서 사용 중인 GSAP으로 표시 숫자를 보간한다. 별도 의존성, 전역 애니메이션 상태, 범용 애니메이션 프레임워크는 추가하지 않는다.

각 표시 컴포넌트는 현재 표시 숫자를 보관한다. 새 유한 숫자를 받으면 GSAP 전환을 시작하고, 매 갱신마다 기존 `formatTokenCount` 또는 `formatCostUsd`로 문자열을 만든다. 컴포넌트가 사라지거나 목표값이 다시 바뀌면 이전 전환을 종료해 오래된 콜백이 화면을 덮어쓰지 않게 한다.

## 하이라이트와 접근성

기존 공통 `value-flash` 키프레임을 재사용한다. 상단 Token·Cost 전용 클래스에서만 지속 시간을 1,500ms로 지정하며, 다른 화면의 기존 900ms 하이라이트는 변경하지 않는다.

`prefers-reduced-motion: reduce`에서는 숫자 보간과 하이라이트 애니메이션을 생략하고 새 값을 즉시 표시한다. 표시 텍스트와 읽기 순서는 유지한다.

## 검증

- Token과 Cost의 증가·감소가 각각 1,500ms 안에 목표값에 도달하는지 확인한다.
- 전환 중 새 목표값을 적용하면 현재 표시값에서 다시 시작하는지 확인한다.
- 같은 값에는 전환과 하이라이트가 재실행되지 않는지 확인한다.
- 숫자와 `—` 사이의 변경은 즉시 반영되고 하이라이트만 적용되는지 확인한다.
- 전환 중에도 Token과 Cost의 기존 표시 형식이 유지되는지 확인한다.
- reduced-motion에서 즉시 최종값이 표시되고 애니메이션이 실행되지 않는지 확인한다.
- 기존 상단 사용량 테스트, 전체 테스트, 빌드와 Sites 테스트를 통과시킨다.

## 범위 제외

- `5H`, `1W`, 세션 수, 실행·대기 수의 숫자 전환
- 다른 화면의 900ms 하이라이트 지속 시간 변경
- 애니메이션 시간 설정 UI
- 새로운 애니메이션 의존성
